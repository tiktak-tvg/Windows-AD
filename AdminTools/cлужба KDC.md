Служба KDC является частью службы центра распространения ключей и отвечает за аутентификацию в домене по протоколу Kerberos.

Если у вас возникли проблемы со службой KDC, вот шаги для диагностики и решения:

Проверка состояния службы KDC

Служба KDC работает на каждом контроллере домена. Убедитесь, что служба запущена.

Проверка связанных служб

Убедитесь, что служба Active Directory Domain Services (AD DS) запущена, так как KDC зависит от нее.

Проверка сетевых настроек

Убедитесь, что контроллер домена имеет правильные настройки DNS и может разрешать имена других контроллеров домена.

Проверка времени

Протокол Kerberos чувствителен к расхождению во времени. Убедитесь, что время на контроллере домена синхронизировано с другими контроллерами и с внешним источником времени.

Проверка журналов событий

Ищите ошибки, связанные с KDC, в журнале событий (Event Viewer) в разделе "Журналы Windows" -> "Система" и "Журналы приложений и служб" -> "Microsoft" -> "Windows" -> "KDC".

Проверка репликации Active Directory

Если репликация AD нарушена, это может повлиять на работу KDC.

Проверка записей DNS

Убедитесь, что в DNS присутствуют записи _kerberos и _kdc для домена.

Если служба KDC не запускается или возникают ошибки, вот некоторые конкретные действия:

Перезапуск службы KDC
Вы можете перезапустить службу KDC через службы (services.msc) или с помощью командной строки:

cmd
net stop kdc
net start kdc
Если служба не останавливается, можно попробовать перезапустить службу "Active Directory Domain Services", которая перезапустит и KDC:

cmd
net stop "Active Directory Domain Services"
net start "Active Directory Domain Services"
Обратите внимание, что остановка AD DS приведет к недоступности контроллера домена на время остановки.

Диагностика с помощью утилиты dcdiag
Запустите комплексную диагностику контроллера домена:

cmd
dcdiag /test:kerberos
Эта команда проверит настройки Kerberos, включая KDC.

Проверка записей DNS для KDC
Убедитесь, что в DNS есть записи для KDC. Вы можете проверить это с помощью nslookup:

cmd
nslookup -type=srv _kerberos._tcp.rosstat.local
nslookup -type=srv _kpasswd._tcp.rosstat.local
Должны быть возвращены записи, указывающие на контроллеры домена.

Проверка времени
Убедитесь, что время на контроллере домена правильное. Для синхронизации времени можно использовать:

cmd
w32tm /resync
Проверка репликации
Если KDC на одном контроллере домена не работает, а на других работает, проблема может быть в репликации. Проверьте репликацию:

cmd
repadmin /replsummary
Восстановление базы данных KDC (в крайнем случае)
Если база данных KDC повреждена, может потребоваться ее восстановление. Однако это сложная процедура, и следует обратиться к документации Microsoft или к специалисту.

Если проблема не решается, необходимо изучить журналы событий для получения более детальной информации об ошибке.

Если вы столкнулись с конкретной ошибкой, укажите ее текст или код, чтобы можно было дать более точный совет.

В журналах событий DNS регистрируются события с идентификаторами 4000 и 4007

Идентификатор события 4000:

DNS-серверу не удалось открыть Active Directory. Этот DNS-сервер настроен на получение и использование информации из каталога для этой зоны и не может загрузить зону без неё. Убедитесь, что Active Directory работает правильно, и перезагрузите зону. Данные события содержат код ошибки.

Идентификатор события 4007:

DNS-серверу не удалось открыть зону <zone> в Active Directory из раздела каталога приложений <partition name>. Этот DNS-сервер настроен на получение и использование информации из каталога для этой зоны и не может загрузить зону без неё. Убедитесь, что Active Directory работает правильно, и перезагрузите зону. Данные события содержат код ошибки.

Кроме того, при попытке открыть консоль DNS появляется всплывающее окно с сообщением « Доступ запрещен» . 

Вы заметили, что служба DNS-сервера запущена и работает.

При попытке выполнить любую операцию в зонах, интегрированных с AD, с помощью DNSCMD возникает ошибка « Доступ запрещён».

Причина
Это происходит, когда данный сервер DC/DNS теряет безопасный канал связи с самим собой или PDC.

Это также может произойти в среде с одним DC, где этот DC/DNS-сервер выполняет все роли FSMO и указывает на себя как на основной DNS-сервер.

Разрешение
Выполните следующую команду с повышенными правами:

net stop kdc
klist purge
netdom resetpwd /server:127.0.0.1 /userd:domain.com\administrator /passwordd:*
net start kdc
Система запросит пароль учетной записи администратора домена, которую вы использовали. Введите его.

После выполнения команды перезапустите службу Active Directory Services.

DNS-зоны теперь должны загрузиться.

Теперь перезагрузите сервер.
