#### Проверка доступности контроллера домена

Убедитесь, что контроллер домена DC-01 вообще доступен и функционирует.

Проверьте, отвечает ли он по сети: **ping DC-01.moscow.local**

Проверьте, запущены ли на нём ключевые службы: Запустите оснастку **services.msc** на DC-01 и убедитесь, что работают:
```bash
Netlogon
DNS Server (если он является DNS-сервером)
Active Directory Domain Services
```
Проверьте, виден ли он в оснастке **"Active Directory пользователи и компьютеры"**: Разверните ветку Domain Controllers – там должен быть компьютерный объект для DC-01.

Попробуйте прореплицировать данные НА проблемный сервер: **repadmin /replicate srv2-DC DC-01 DC=moscow,DC=local**

Также проверьте, что на DC опубликованы сетевые папки SYSVOL и Netlogon:
```bash
net share
```
Далее обязательно проверьте синхронизацию времени на контроллерах домена командой:
```bash
w32tm /monitor
```

Для проверки состояния репликации между контроллерами в домене используется встроенная утилита repadmin. Базовая команда проверки входящей и исходящей репликации:
```bash
repadmin /replsum
```
Утилита вернет текущий статус репликации между всеми DC. В идеальном случае значение largest delta не должно превышать 1 час (зависит от топологии и настроек частоты межсайтовых репликаций), а количество ошибок replication fails = 0. В моем примере видно, что одна из последних репликаций заняла 14 дней, но сейчас все OK.

Чтобы выполнить проверку репликации для всех DC в домене:
```bash
repadmin /replsum *
```
Проверка межсайтовой репликации:
```bash
repadmin /showism
```
Для просмотра топологии репликации и найденных ошибках, выполните:
```bash
repadmin /showrepl
```
Для вывода расширенной информации, используйте:
```bash
repadmin /showrepl *
```
Для запуска принудительной синхронизации указанного DC со всеми партнерами по репликации, используйте команду
```bash
repadmin /syncall
```
Если нужно принудительно заставить контроллер домена получить изменения с других DC, исопльзуется команда:
```bash
repadmin /syncall /Ade
```
Для просмотра очереди репликации:
```bash
replmon /syncall <nameDC>
```
Для просмотра очереди репликации:
```bash
repadmin /queue
```
Проверьте время создания последней резервной копии текущего контроллера домена:
```bash
Repadmin /showbackup *
```
Это более общая команда, которая заставляет целевой сервер синхронизироваться со всеми своими партнерами по репликации для всех разделов.
```bash
cmd
repadmin /syncall /A /e /P
```
Расшифровка ключей:

- **/A** — синхронизировать все разделы AD (Domain, Config, Schema).

- **/e** — синхронизироваться со всеми партнерами по репликации (межсайтовыми в том числе).

- **/P** — приостановить запрос на выполнение команды, если какой-либо из партнеров недоступен.

Просто выполните эту команду на том контроллере домена, который должен получить актуальные данные.

```cmd
C:\Windows\system32>repadmin /?
Пример:
            repadmin <команда> <аргументы> [/u:{домен\пользователь}]
                                           [/pw:{пароль|*}][/retry[:<повторы>]
                                           [:<задержка>]]     [/csv]

Следующие команды предназначены для отображения справочных сведений:

/?               Отображение списка команд, доступных для использования в
                 команде repadmin и их описания.
/help            Совпадает с /?
/?:<команда>     Отображение списка возможных аргументов <аргументы>,
                 соответствующего синтаксиса и примеров для указанной
                 команды <команда>.
/help:<команда>  Совпадает с /?:<команда>
/experthelp      Отображение списка команд, предназначенных для использования
                 только опытными пользователями.
/listhelp        Отображение вариаций синтаксиса для строк DSA_NAME,
                 DSA_LIST, NCNAME и OBJ_LIST.
/oldhelp         Отображение списка устаревших команд, которые по-прежнему
                 работают, но более не поддерживаются корпорацией Майкрософт.


Поддерживаемые команды <команда> (введите /?<cmd> для получения подробных
справочных сведений):
     /kcc    Принуждает KCC на назначенных контроллерах домена немедленно
             перерасчитать входящую топологию репликации.

     /prp    С помощью этой команды администратор может просматривать и
             изменять политику репликации паролей для RODC.

     /queue  Отображает запросы входящей репликации, которые необходимо
             обработать контроллеру домена, чтобы соответствовать его исходным
             партнерам репликации.

     /replicate  Немедленно запускает репликацию указанного раздела
            каталогов на конечный контроллер домена из исходного контроллера
            домена.

     /replsingleobj Реплицирует отдельный объект между двумя контроллерами
             домена, имеющими общие разделы каталогов.

     /replsummary Операция replsummary быстро и кратко обобщает
             состояние репликации и относительную работоспособность леса.

     /rodcpwdrepl Запускает репликацию паролей для заданных пользователей
             с источника (контроллера домена концентратора) на один или более
             доступных только для чтения контроллер домена.

     /showattr Отображает атрибуты объекта.

     /showobjmeta Отображает метаданные репликации для указанного объекта,
             хранящиеся в Active Directory, например, идентификатор атрибута,
             номер версии, исходящий и локальный USN, а также GUID исходящего
             сервера и метку даты и времени.

     /showrepl Отображает состояние репликации, когда указанный контроллер
             домена последний раз пытался выполнить входящую репликацию
             разделов Active Directory.

     /showutdvec Отображает наибольший поддерживаемый последовательный номер
            обновления (USN), который в указанной копии контроллера домена
            Active Directory показан как поддерживаемый для этой копии и
            транзитивных партнеров.

     /syncall Синхронизирует указанный контроллер домена со всеми партнерами
              репликации.

Поддерживаемые дополнительные параметры:

     /u:    Указание домена и имени пользователя с обратной косой чертой в
            качестве разделителя {домен\пользователь}, у которого имеются
            разрешения на выполнение операций Active Directory. UPN-вход не
            поддерживается.

     /pw:   Задание пароля для имени пользователя, указанного в параметре /u.

     /retry Этот параметр вызывает повтор попытки создать привязку к конечному
            контроллеру домена, когда при первой попытке произошел сбой с одним
            из следующих состояний ошибки:

            1722 / 0x6ba : "Сервер RPC недоступен"
            1753 / 0x6d9 : "Отсутствуют конечные точки, доступные из
                            сопоставителя конечных точек"

     /csv   Применяется с параметром /showrepl для вывода результатов в формате
            значений, разделенных запятыми. См. /csvhelp


Примечание. Большинство команд принимают параметры в следующем порядке:
           "Конечный DSA_LIST", затем "Исходное DSA_NAME" (если требуется) и,
           наконец, NC или DN объекта (если требуется).

        <DSA_LIST> (или <DSA_NAME>) - это строка привязки DSA.
        Для доменных служб Active Directory это просто сетевая идентификация
        контроллера домена (такая как DNS, NetBios или IP-адрес).
        Для служб Active Directory облегченного доступа к каталогам это должно
        быть сетевой идентификацией сервера AD LDS, за которой следует
        двоеточие и номер LDAP-порта экземпляра AD LDS
            Примеры (AD DS):  dc-01
                               dc-01.microsoft.com
            Примеры (AD LDS): ad-am-01:2000
                               ad-am-01.microsoft.com:2000

      <Контекст именования> - различающееся имя корня NC
            Пример: DC=My-Domain,DC=Microsoft,DC=Com
Примечание. Текст (имена контекста именования, имена серверов и др.),
            содержащий знаки национальных алфавитов или Юникода, будет
            отображаться правильно только в том случае, если загружены
            соответствующие шрифты и языковая поддержка.

C:\Windows\system32>

```
