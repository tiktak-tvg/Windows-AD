### AD CS (Active Directory Certificate Services) — это роль сервера Windows Server, которая позволяет создавать, управлять и отзывать цифровыми сертификатами в корпоративной инфраструктуре. 
Это основа для реализации инфраструктуры открытых ключей (PKI) в среде Active Directory.

#### Основное назначение AD CS:

**Предоставление цифровых сертификатов для:**

- Аутентификации пользователей, компьютеров и устройств.

- Шифрования данных (например, для VPN, электронной почты, дисков BitLocker).

- Цифровой подписи документов и кода.

- Защищённого веб-доступа (HTTPS) для внутренних сайтов.

- Умных карт (smart card) для входа в систему.

#### Ключевые компоненты AD CS:

**Центр сертификации (CA — Certification Authority):**

  - Корневой CA — самый верхний уровень доверия (обычно изолирован от сети).

  - Промежуточный CA — подчиняется корневому, выдаёт сертификаты конечным объектам.

  - Выдающий CA — непосредственно выпускает сертификаты.

**Служба регистрации (Certificate Enrollment Service):**

  - Позволяет пользователям и компьютерам запрашивать сертификаты через веб-интерфейс или автоматически.

**Служба веб-регистрации (Certificate Enrollment Web Service):**

  - Веб-портал для запроса и установки сертификатов.

**Список отозванных сертификатов (CRL — Certificate Revocation List):**

  - Публикуемый список сертификатов, которые были отозваны до истечения срока действия.

**Служба онлайн-отзыва (OCSP — Online Certificate Status Protocol):**

  - Проверка действительности сертификатов в реальном времени (альтернатива CRL).

#### Типы развёртывания CA:

**Enterprise CA** — интегрируется с Active Directory:

- Автоматическая регистрация сертификатов через групповые политики.

- Хранение шаблонов сертификатов в AD.

- Использование учётных записей домена для аутентификации.

**Standalone CA** — работает независимо от AD:

- Вручную утверждает запросы (по умолчанию).

- Часто используется для изолированных систем или корневых CA.

#### Типичные сценарии использования AD CS:

- **Защита Wi-Fi (802.1X)** — сертификаты для аутентификации устройств в сети.

- **VPN (IPsec/IKEv2)** — сертификаты для удалённого доступа.

- **Шифрование дисков BitLocker** — сертификаты для восстановления данных.

- **Цифровая подпись приложений и драйверов.**

- **Аутентификация веб-серверов (внутренние сайты).**

- **Умные карты для двухфакторной аутентификации.**

#### Пример работы AD CS:

- Администратор настраивает шаблон сертификата «Компьютер для VPN».

- Через групповую политику компьютерам назначается автоматическая регистрация.

- Компьютер при запуске запрашивает сертификат у Enterprise CA.

- CA проверяет права через AD и выдаёт сертификат.

- Компьютер использует сертификат для подключения к корпоративной VPN.

#### Важные аспекты безопасности AD CS:

- Корневой CA должен быть **отключён** от сети (изоляция).

- Регулярное резервное **копирование** закрытых ключей CA.

- Мониторинг **несанкционированной** выдачи сертификатов.

- Использование **строгих алгоритмов** шифрования (SHA-256, RSA 2048+).

- Настройка **автоматического продления** сертификатов.

#### Отличие от публичных центров сертификации (как Let's Encrypt):

- AD CS используется внутри организации, а публичные CA (GlobalSign, DigiCert) — для публичных ресурсов в интернете. Сертификаты от AD CS доверяют только устройства, настроенные доверять вашему корневому CA.
