### AD FS (Active Directory Federation Services) — это служба единого входа (SSO — Single Sign-On), разработанная Microsoft. Она позволяет пользователям аутентифицироваться один раз с помощью своих корпоративных учётных данных (обычно из Active Directory), чтобы получать доступ к нескольким приложениям — как внутри сети, так и в облаке — без необходимости повторного ввода пароля.

#### Основная цель AD FS:
- Обеспечить федеративный доступ — безопасное разделение аутентификации между разными доменами, организациями или платформами, используя стандартные протоколы.

#### Ключевые термины:
- Федерация (Federation) — отношения доверия между двумя организациями, позволяющие совместно использовать аутентификацию.

- Поставщик удостоверений (Identity Provider — IdP) — сторона, которая хранит учётные данные и выполняет аутентификацию (например, ваша AD).

- Поставщик услуг (Service Provider — SP) — приложение или служба, к которой пользователь хочет получить доступ (например, Salesforce, Office 365).

- Утверждение (Claim) — информация о пользователе (например, имя, группа, роль), которую IdP передаёт SP после успешной аутентификации.

#### Как работает AD FS (базовый сценарий):
- Пользователь пытается получить доступ к облачному приложению (например, Office 365).

- Приложение перенаправляет пользователя на AD FS (IdP).

- AD FS запрашивает учётные данные (логин/пароль, smart card, Windows Hello).

- После аутентификации в Active Directory AD FS создаёт токен безопасности с утверждениями (claims) о пользователе.

- Токен отправляется обратно в приложение.

- Приложение доверяет токену от AD FS и предоставляет доступ.

> Результат: Пользователь вошёл в облачное приложение, используя локальный пароль AD.

#### Основные компоненты AD FS:
- Сервер федерации (Federation Server) — основной компонент, обрабатывающий запросы на аутентификацию и выдачу токенов.

- Прокси-сервер федерации (Federation Server Proxy) — размещается в DMZ для безопасного приёма внешних запросов.

- База данных конфигурации — хранит настройки доверия, обычно в базе данных SQL Server или Windows Internal Database.

- Веб-портал управления AD FS — интерфейс настройки отношений доверия и мониторинга.

#### Поддерживаемые протоколы:
- SAML 2.0 — самый распространённый стандарт для федерации с SaaS-приложениями (Salesforce, Google Workspace).

- WS-Federation — часто используется для интеграции с Microsoft-сервисами.

- OAuth 2.0 / OpenID Connect — современные протоколы для веб- и мобильных приложений (AD FS поддерживает с версии 2016).

#### Минусы AD FS:
- Сложность развёртывания — требует нескольких серверов (ферма), балансировки нагрузки, SSL-сертификатов.

- Единая точка отказа — если AD FS недоступен, внешние приложения не работают.

- Затраты на инфраструктуру — лицензии Windows Server, SSL-сертификаты, мониторинг.

#### Безопасность AD FS:
- Рекомендуется использовать WAP (Web Application Proxy) для публикации AD FS в интернете.

- Регулярное обновление для устранения уязвимостей (например, связанных с SAML-токенами).

- Мониторинг попыток взлома (атаки на пароли, подделка токенов).
